<objective>
Ship the two pure presentation components the detail route composes: `<RepoDetail>` for the success state and `<RateLimitPanel>` for the specific failure state that the App Router error boundary cannot handle (the `RATE_LIMIT` code that lives in a returned `Result`, per Phase 1 D-01 / D-05a).

Purpose: keeping presentation out of `page.tsx` means the route stays thin — one server-side fetch, a `switch` on the `Result`, and delegation to a component — which is exactly what makes DTL-04 (direct URL or refresh) trivial to prove. Colocated tests here also close TEST-02's detail half without needing a full route render harness, which the component layer does not offer.

Output: `RepoDetail.tsx` rendering the seven brief-required fields plus the back link, `RateLimitPanel.tsx` rendering the reset time in Asia/Tokyo Japanese copy, and colocated tests for both queried by role and accessible name.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub repository description / name → rendered DOM | Untrusted input; the ban on `dangerouslySetInnerHTML` (SEC-03, enforced by the Phase 1 lint rule) closes the injection path. Every string reaches the DOM as text |
| Rate-limit reset time → user copy | An unformatted Unix seconds value would communicate nothing; a badly-formatted string in an unstated timezone is worse than none. Format explicitly in Asia/Tokyo and say so in the copy |
| Owner avatar URL → `next/image` | The origin check happens in the framework via the allowlist landed in 03-01. This plan does not re-check it — the fixture in tests uses the allowlisted host so a mistaken host would be caught by the build, not by an assertion here |
