    - `resolveBackTarget(undefined)` returns `"/"`
    - `resolveBackTarget("")` returns `"/"`
    - `resolveBackTarget(["/x", "/y"])` returns `"/"` — an array-shaped query param is not a legitimate back link, drop it

    - `resolveBackTarget("https://evil.example.com")` returns `"/"`
    - `resolveBackTarget("javascript:alert(1)")` returns `"/"` — an obvious XSS attempt via `href=`

**`src/lib/backTarget.ts`** should:

- Export exactly one function with the signature above.
- Use the same regex shape as `src/lib/github/client.ts`'s `SITE_RELATIVE_PATH` (`^\/[^/\\]/`). The important properties: the URL must begin with a single `/`, and its second character must be neither `/` nor `\`. Special-case `"/"` (the root) so it returns `"/"` — that is the fallback, and it must not fail its own guard.
- Handle three input shapes at the top of the function: `undefined`, `""`, and `string[]`. All fall back to `"/"`. The type is `string | string[] | undefined` because that is what Next.js gives you for a query param — anything else in the test file is a bug in the test.
- Carry a top-of-file comment explaining that it mirrors `SITE_RELATIVE_PATH` from `client.ts`, and pointing at the WHATWG-URL trap that the double-character check exists to close. Same reasoning, same regex — a reader should see they say the same thing.
- Never import from `src/lib/github/**`. Phase 1's client is a server-side module and this helper is called from what will become a Server Component route; keeping them separate keeps the boundary clean and lets Phase 4's Client Component work import this helper without a lint fight.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `?from` query param → back link `href` | An attacker who plants a link with a crafted `from` value could hijack the back button to an arbitrary origin, which reads as a bug and would be a real open-redirect on any auth flow bolted on later |
| Owner avatar URL → `next/image` optimiser | Without an explicit allowlist, the Next image optimiser will proxy any URL passed to `src`, effectively making the app an image proxy for the wider internet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | The back link `href` | mitigate | `resolveBackTarget` rejects every form that resolves to another origin; the test names each rejected form so a future change that weakens the guard fails a named test rather than silently regressing |
| T-03-02 | Elevation of privilege | Next's remote image optimiser | mitigate | `images.remotePatterns` is a single-host entry, https-only; no wildcards, no subdomain globs (SEC-02) |
| T-03-SC | Tampering | npm installs | mitigate | Zero new production dependencies in this plan. The `git diff --stat package.json package-lock.json` check in 03-03's gate covers the whole phase |
</threat_model>
