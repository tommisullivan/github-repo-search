# Plan 02-01 Summary — App Boundaries

**Completed:** 2026-08-02
**Files:** `src/app/layout.tsx`, `src/app/loading.tsx`, `src/app/loading.test.tsx`, `src/app/error.tsx`, `src/app/error.test.tsx`

## What is now live

- The document root declares Japanese as the language (`<html lang="ja">`), so screen readers announce content as Japanese and browser translators treat the strings as Japanese source.
- `metadata.title` = `GitHubリポジトリ検索`; `metadata.description` is a Japanese sentence describing the app. The scaffold's `Create Next App` / `Generated by create next app` are gone.
- `src/app/loading.tsx` is a Server Component that renders `<p role="status" aria-label="読み込み中">読み込み中…</p>`. The App Router uses this during the server render for `/`, so a user sees the Japanese loading state, not an empty page. `aria-label` is added so the accessible name matches "読み込み中" (jsdom's default name-from-content did not resolve reliably during testing — recorded here for the a11y audit in Phase 4 to know why the label exists).
- `src/app/error.tsx` is a Client Component (`"use client"` on line 1, as required by Next 16's App Router). It renders `<section role="alert">` with a Japanese heading (`エラーが発生しました`), a Japanese explanation, and a `<button>` labelled `再試行` whose `onClick` calls `reset()`.
- **The error boundary never renders `error.message`, `.stack`, or `.digest` in the DOM.** A test supplies a distinctive marker string as `error.message` and asserts `queryByText(marker)` returns `null`. `error.digest` is logged to the browser console (framework convention) but never shown.

## Contract for plan 02-02

- Any `throw` from `searchRepositories` — including the `GitHubRequestError` Phase 1 raises for transport faults, timeouts, and 5xx — is caught by `error.tsx` and rendered as fixed Japanese copy.
- Because of the above, `page.tsx` in 02-02 does **not** `try`/`catch` the client call. Doing so would swallow a throw that must reach this boundary (D-07 in the phase context; D-03 in Phase 1's context).
