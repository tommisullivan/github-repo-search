<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test-only mock → production runtime | The interceptor ships in the build; if it activated outside E2E it would serve fabricated data to real users |
| E2E process → live GitHub API | An interception gap would leak CI traffic to the rate-limited live API and make the suite flaky or dishonest |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | `src/lib/e2e/githubApiMock.ts` | mitigate | Double env-gate (`NEXT_RUNTIME` + `E2E_GITHUB_MOCK=1`) set only by the Playwright webServer; register() is a no-op otherwise; fixtures carry sentinel names so accidental activation is visible instantly, not subtle |
| T-04-02 | Information disclosure | outbound `Authorization` header | mitigate | No configurable base URL introduced (T-01-26 honoured); interception happens beneath the sealed client with the URL unchanged, so the token cannot be redirected by configuration |
| T-04-03 | Denial of service (CI flake) | unmatched api.github.com requests | mitigate | Sentinel 500, never pass-through — the no-live-API rule is enforced by the mock's default branch, not by spec discipline |
| T-04-SC | Tampering | npm installs | mitigate | Zero new dependencies in this plan (MSW explicitly rejected, D4-01); `git diff --stat package.json package-lock.json` empty, checked in 04-05's phase gate |
</threat_model>
